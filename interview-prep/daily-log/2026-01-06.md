# Daily Interview Prep — January 06, 2026

Five questions worked through this session.

---

### Q1. What is A* search?

**Answer.** Best-first search over a graph with cost = g(n) (cost so far) + h(n) (heuristic estimate to goal). With an admissible (never overestimating) heuristic it finds the optimal path; h = 0 reduces to Dijkstra, h = g reduces to greedy best-first. Used in pathfinding and game AI.

---

### Q2. Explain the divide and conquer pattern.

**Answer.** Split the problem into independent subproblems, solve each recursively, combine the results. The recurrence is T(n) = aT(n/b) + O(n^d); the Master Theorem compares a/b^d to decide the bound. Examples: merge sort, matrix multiplication, closest pair.

---

### Q3. How do you find the kth largest element faster than sorting?

**Answer.** Quickselect: partition like quicksort but recurse only into the side containing the kth element — average O(n), worst O(n^2) (fix with median-of-medians pivot or randomization). Or a size-k min-heap: O(n log k), which wins when k << n.

---

### Q4. What is the difference between BFS and Dijkstra on unweighted graphs?

**Answer.** On unweighted graphs Dijkstra degenerates to BFS — every relaxation has the same unit cost, so the heap never reorders anything. BFS is the simpler, faster choice there; keep Dijkstra for weighted edges.

---

### Q5. When would you use BFS on an adjacency list vs matrix?

**Answer.** Adjacency list: O(V + E) memory, ideal for sparse graphs (the common case). Matrix: O(V^2) memory but O(1) edge-existence checks and easy to combine with matrix operations — fine for dense graphs or small V with repeated queries.

---

### Q6. Horizontal vs vertical scaling?

**Answer.** Vertical: bigger machine — simple but capped by hardware and a single point of failure. Horizontal: more machines — requires statelessness or sharded/replicated state, load balancing, and network-aware code, but scales past any single box and allows rolling deploys.

---

### Q7. What is sharding and how do you choose a shard key?

**Answer.** Partition data across databases by a key: hash sharding spreads evenly (but range queries hit all shards), range sharding keeps locality (but risks hot ranges). Choose the key from your query patterns — a hot key (e.g. one user's 1B feed) skews load, so you may double-key (user_id, post_id).

---

### Q8. Explain database replication and the consistency tradeoff.

**Answer.** A primary writes, followers apply via the write-ahead log (async: fast, can lose commits on failover; semi-sync: at least one follower acks; sync: safest, slowest). Reads can go to followers for scale but may return stale data — mitigate with read-your-writes, session tokens, or fencing.

---

### Q9. What is consistent hashing and why do databases/CDNs use it?

**Answer.** Place nodes and keys on a ring (hash space); a key maps to the next node clockwise. Adding/removing a node moves only ~1/n of keys instead of reshuffling everything. Virtual nodes (replicas of a physical node on the ring) even out load and latency.

---

### Q10. How does a CDN work?

**Answer.** An edge network of caches geographically near users, addressed via DNS (CNAME to the CDN, then anycast/nearest-edge selection). Cacheable assets (HTML, JS, media) are served from the edge with cache-control keys; the origin only sees cache misses, cuts latency, and absorbs traffic spikes.
