# Daily Interview Prep — January 12, 2026

Five questions worked through this session.

---

### Q1. What is a B-tree and why do databases use it for indexes?

**Answer.** A multi-way balanced tree where each node holds many keys and child pointers, tuned so one node = one disk page. Height ~3-4 holds hundreds of millions of keys, so a point lookup is 3-4 page reads. Range scans are sequential page walks — better locality than a B+tree's leaf linked list... (B+trees are the usual choice; B-trees store data in all nodes).

---

### Q2. What is a database connection pool and why is it needed?

**Answer.** Connections are expensive to create (TCP + auth + TLS, tens of ms); a pool keeps N warm connections for the app to borrow/return. Pool size must respect the DB's max_connections — a common outage: 200 app nodes x pool of 20 = 4000 connections vs DB limit 1000. PgBouncer proxies to share physical connections.

---

### Q3. What does idempotency mean and how do you make writes idempotent?

**Answer.** Repeating the operation has no additional effect. Techniques: client-generated idempotency keys deduplicated server-side, PUT (replace, not append) semantics, and unique constraints (re-insert hits the constraint instead of duplicating). Needed for retries over networks where 'did it land?' is unknowable.

---

### Q4. How would you design a short URL service (bit.ly)?

**Answer.** Hash the long URL (or use a monotonic counter / base62 of an auto-increment id) to a 7-char code — counter avoids hash collisions and is cache-friendly. Store code->URL in a KV store or sharded DB, 301 redirect (caches the mapping in browsers) or 302 if you need click analytics. Handle load with a CDN + hot-key replication.

---

### Q5. What is a write-ahead log (WAL) and why is it important?

**Answer.** Every change is appended to a durable log before being applied to the data structures; crash recovery replays the log (redo) and rolls back uncommitted work (undo). It's what makes a database durable after a power loss, and the same log powers replication, point-in-time recovery, and compaction in LSM stores.

---

### Q6. Why is merge sort O(n log n) always, and what does it cost?

**Answer.** It splits in half (log n levels) and each level merges in O(n). Guarantees n log n regardless of input and is stable, but needs O(n) auxiliary space — that's the cost.

---

### Q7. What is a count sort / radix sort and when is it valid?

**Answer.** Counting sort buckets by integer value in O(n + k) — linear when k is bounded, so it beats comparison sort's n log n floor. Radix sort generalizes it digit-by-digit. Only works on bounded integers (or fixed-length keys).

---

### Q8. What do we mean when we say an algorithm is O(n log n)?

**Answer.** Runtime grows proportionally to n log n: n log n = n x log n, n x log2 n = n x 10. Big-O hides constants and lower-order terms, so 10n log n is also O(n log n). It describes the asymptotic upper bound of the worst-case behavior we analyzed.

---

### Q9. Explain the two-pointer technique.

**Answer.** Keep left and right pointers moving inward (or both moving forward) to exploit monotonic structure — sorted arrays, prefix structure, window validity. Reduces brute-force O(n^2) to O(n) for problems like two-sum on sorted arrays, container-with-most-water, and palindrome checks.

---

### Q10. When is binary search the right tool, and what's the classic bug?

**Answer.** Use it on any monotonic predicate (sorted array, or 'find first true over a boolean space'), giving O(log n). Classic bugs: integer overflow in mid = (lo+hi)/2 (use lo + (hi-lo)/2), off-by-one on update bounds, and wrong loop invariant (use [lo, hi) or consistently <=).

---

### Q11. Describe Dijkstra's algorithm and its limitation.

**Answer.** Greedy shortest-path from one source using a min-heap: settle the closest unsettled node, relax edges. O((V+E) log V). Fails with negative edge weights because a settled node's distance can still decrease — use Bellman-Ford there.

---

### Q12. What is dynamic programming, and what makes a problem solvable with it?

**Answer.** Break a problem into overlapping subproblems, solve each once, store the result (memoization/table). Requirements: optimal substructure (optimal solution built from optimal sub-solutions) and overlapping subproblems. Example: Fibonacci, knapsack, longest common subsequence.

---

### Q13. Memoization vs tabulation?

**Answer.** Memoization is top-down recursion with a cache; tabulation is bottom-up iteration filling a table. Same complexity; tabulation removes recursion overhead and can enable space reduction (keep only the last 2 rows), while memoization is often easier to derive from the recurrence.
