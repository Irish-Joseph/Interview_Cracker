# Daily Interview Prep — January 26, 2026

Five questions worked through this session.

---

### Q1. What is HTTP/2 and how does it fix head-of-line blocking at one layer but create it at another?

**Answer.** Multiplexes many streams over one TCP connection with binary framing and header compression (HPACK), killing HTTP/1.1's one-request-per-connection stalls. But TCP-level retransmission still blocks all streams — that's why HTTP/3 moved to QUIC/UDP.

---

### Q2. What is a file descriptor and why is it just an integer?

**Answer.** An index into the per-process table of open file handles (socket, pipe, regular file, terminal). Everything is a stream of bytes to the kernel, so dup/pipe/redirect work uniformly — /dev/null, socket 3, and an open file all share the same syscall interface.

---

### Q3. Explain how DNS works in a few sentences.

**Answer.** The resolver queries a recursive resolver, which walks the hierarchy: root servers point to the TLD (.com) servers, which point to the authoritative nameserver for the domain, which answers the A/AAAA/CNAME record. Results are cached at every level per TTL.

---

### Q4. What is the difference between a signal and an exception?

**Answer.** A signal is an asynchronous OS-level interrupt delivered to a process/thread (SIGTERM, SIGKILL, SIGSEGV); a process can install handlers or ignore it, but SIGKILL/SIGSTOP cannot be caught. An exception is a synchronous, in-language control flow mechanism for errors at a known instruction.

---

### Q5. What is the CAP theorem and what do real systems choose?

**Answer.** A distributed system cannot simultaneously guarantee Consistency, Availability, and Partition tolerance — and partitions happen, so the real choice is CP (refuse requests during a partition, e.g. ZooKeeper) or AP (serve stale data, e.g. DynamoDB).

---

### Q6. What is rate limiting and name three strategies?

**Answer.** Bounded request acceptance per client/window. Token bucket (smooth bursts up to the bucket size), leaky bucket (constant outflow, smooths bursts), fixed/sliding window counters (simple, counter at window boundaries). Distributed deployments put the counters in Redis with atomic scripts or use an API gateway.

---

### Q7. What is a message queue and when would you use Kafka vs RabbitMQ?

**Answer.** A broker that decouples producers from consumers via durable, asynchronous messages. Kafka is a replicated, partitioned log — high throughput, replayable, event-sourcing/audit trails. RabbitMQ is a flexible work-queue router — lower latency per message, rich routing, but not a replay log.

---

### Q8. Microservices vs monolith?

**Answer.** Monolith: one deployable, shared database, simple transactions and debugging, coupled releases. Microservices: independent deploy/scale per service, polyglot persistence, isolated failure domains — at the cost of network latency, distributed-transaction complexity (sagas), and operational burden (tracing, versioning contracts).
