# Daily Interview Prep — January 31, 2026

Five questions worked through this session.

---

### Q1. What is a covering index?

**Answer.** An index that contains all columns the query needs (e.g. INCLUDE in PostgreSQL, or a composite wide enough), so the query is answered from the index alone — no heap 'bookmark lookups'. Common in OLTP for 'index-only scans' on hot read paths.

---

### Q2. Explain a B+tree index.

**Answer.** All data (or row pointers) lives in the leaf level, leaves are linked for range scans, and interior nodes are pure routing keys. Balanced and shallow (3-4 levels for hundreds of millions of rows). The leaf linked list makes sequential range reads a scan of adjacent pages — great for locality.

---

### Q3. What is a deadlock in a database and how do DBs handle it?

**Answer.** Two transactions each lock rows the other needs (T1 locks A waits for B; T2 locks B waits for A). MySQL InnoDB detects via a wait-for graph and kills the victim (ER_LOCK_DEADLOCK); PostgreSQL waits up to deadlock_timeout then detects and aborts one transaction. App fix: consistent lock ordering, short transactions, retry with backoff.

---

### Q4. What are dirty, non-repeatable and phantom reads?

**Answer.** Dirty read: reading another transaction's uncommitted data (lost if it rolls back). Non-repeatable read: re-reading a committed row that another committed transaction changed. Phantom read: a re-run of a range query returns new rows inserted by another committed transaction. Each maps to the isolation levels above.

---

### Q5. How does a JOIN actually execute?

**Answer.** The planner picks a strategy: nested loop (probe inner per outer row — good with cheap indexes or tiny outer), hash join (build a hash of the smaller side, probe with the larger — the default for large unindexed joins), or merge join (both sides sorted on the key — good for ranges). EXPLAIN shows which one and its estimated cost.

---

### Q6. What is the difference between a stack and a queue?

**Answer.** A stack is LIFO — push/pop both happen at the same end; a queue is FIFO — enqueue at the back, dequeue from the front. Stacks model undo, call frames, backtracking; queues model task scheduling, BFS, rate limiting.

---

### Q7. Why does a hash table give O(1) average lookup?

**Answer.** The key is passed through a hash function to index the bucket directly, skipping the scan. It degrades to O(n) when collisions cluster (poor hash or load factor too high), so implementations resize at ~0.7 load and use chaining or open addressing.

---

### Q8. What is a binary search tree and when does it degrade?

**Answer.** A BST keeps left < node < right, giving O(log n) search/insert on average. It degrades to O(n) when the tree becomes a chain (sorted insertions), which is why balanced variants (AVL, red-black) exist.

---

### Q9. Explain a min-heap and its typical use.

**Answer.** A complete binary tree stored in an array where each parent <= its children, so the root is always the minimum. Insert/sift is O(log n); it powers priority queues, top-k problems, Dijkstra, and merge-k-sorted-lists.

---

### Q10. How does an LRU cache work?

**Answer.** A hash map from key to node plus a doubly linked list for recency. On hit, move the node to the front; on insert, evict the back. Both operations are O(1).
