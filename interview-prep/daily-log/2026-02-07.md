# Daily Interview Prep — February 07, 2026

Five questions worked through this session.

---

### Q1. When is binary search the right tool, and what's the classic bug?

**Answer.** Use it on any monotonic predicate (sorted array, or 'find first true over a boolean space'), giving O(log n). Classic bugs: integer overflow in mid = (lo+hi)/2 (use lo + (hi-lo)/2), off-by-one on update bounds, and wrong loop invariant (use [lo, hi) or consistently <=).

---

### Q2. Describe Dijkstra's algorithm and its limitation.

**Answer.** Greedy shortest-path from one source using a min-heap: settle the closest unsettled node, relax edges. O((V+E) log V). Fails with negative edge weights because a settled node's distance can still decrease — use Bellman-Ford there.

---

### Q3. What is dynamic programming, and what makes a problem solvable with it?

**Answer.** Break a problem into overlapping subproblems, solve each once, store the result (memoization/table). Requirements: optimal substructure (optimal solution built from optimal sub-solutions) and overlapping subproblems. Example: Fibonacci, knapsack, longest common subsequence.

---

### Q4. Memoization vs tabulation?

**Answer.** Memoization is top-down recursion with a cache; tabulation is bottom-up iteration filling a table. Same complexity; tabulation removes recursion overhead and can enable space reduction (keep only the last 2 rows), while memoization is often easier to derive from the recurrence.

---

### Q5. What is backtracking?

**Answer.** Build a solution incrementally, and prune the branch as soon as a constraint is violated. Exploring all valid arrangements (N-queens, Sudoku, permutations, subsets) with pruning. Key: make a choice, recurse, undo the choice.

---

### Q6. How does a load balancer work and what are the common algorithms?

**Answer.** It front-ends a pool of servers and routes each connection using round-robin, least-connections, or consistent hashing (minimizes cache invalidation when nodes change). L4 operates on IP/TCP; L7 inspects HTTP (path, headers) and can add TLS termination, retries, and rate limiting.

---

### Q7. Horizontal vs vertical scaling?

**Answer.** Vertical: bigger machine — simple but capped by hardware and a single point of failure. Horizontal: more machines — requires statelessness or sharded/replicated state, load balancing, and network-aware code, but scales past any single box and allows rolling deploys.

---

### Q8. What is sharding and how do you choose a shard key?

**Answer.** Partition data across databases by a key: hash sharding spreads evenly (but range queries hit all shards), range sharding keeps locality (but risks hot ranges). Choose the key from your query patterns — a hot key (e.g. one user's 1B feed) skews load, so you may double-key (user_id, post_id).
