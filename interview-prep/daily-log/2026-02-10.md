# Daily Interview Prep — February 10, 2026

Five questions worked through this session.

---

### Q1. TCP vs UDP?

**Answer.** TCP: connection-oriented, reliable, in-order delivery with retransmission, flow and congestion control — for HTTP, databases. UDP: connectionless, no ordering or retransmit, tiny header — for video, DNS, game state, where a late packet is worse than a lost one. QUIC layers reliable streams over UDP.

---

### Q2. What happens when you type a URL and press enter?

**Answer.** DNS resolution (cache -> resolver -> root/TLD/authoritative servers), TCP handshake with the server, then the TLS handshake (certificate validation, key exchange), then the HTTP request/response. The browser parses HTML, fetches sub-resources, and renders.

---

### Q3. What is a deadlock and what are its conditions?

**Answer.** Two or more threads each hold a resource the other needs, so none can proceed. Needs four conditions (Coffman): mutual exclusion, hold-and-wait, no preemption, circular wait. Break any one — common practice: impose a global lock ordering to kill circular wait, or use try-lock with timeout/backoff.

---

### Q4. What is a context switch and what does it cost?

**Answer.** The OS saving the current thread's CPU state (registers, PC, stack pointer) to its PCB and restoring another thread's. Costs a few microseconds plus cache/TLB pollution — millions of involuntary switches per second can dominate runtime, which is why thread pools exist.

---

### Q5. Explain TCP three-way handshake and why three packets?

**Answer.** Client SYN(seq=x) -> server SYN-ACK(seq=y, ack=x+1) -> client ACK(ack=y+1). Three packets ensure both sides' send and receive paths work and both initial sequence numbers are exchanged. Two would leave one direction unconfirmed and allows stale duplicated SYNs to open connections.

---

### Q6. What are dirty, non-repeatable and phantom reads?

**Answer.** Dirty read: reading another transaction's uncommitted data (lost if it rolls back). Non-repeatable read: re-reading a committed row that another committed transaction changed. Phantom read: a re-run of a range query returns new rows inserted by another committed transaction. Each maps to the isolation levels above.

---

### Q7. How does a JOIN actually execute?

**Answer.** The planner picks a strategy: nested loop (probe inner per outer row — good with cheap indexes or tiny outer), hash join (build a hash of the smaller side, probe with the larger — the default for large unindexed joins), or merge join (both sides sorted on the key — good for ranges). EXPLAIN shows which one and its estimated cost.

---

### Q8. What is an ORM and what are its classic performance problems?

**Answer.** A library mapping objects to tables (SQLAlchemy, Hibernate). Classic problems: the N+1 query (looping entities and loading each relation lazily — fix with eager join/IN batch), over-fetching with big eager graphs, writing the whole object back (lost updates on concurrent writes), and hiding the SQL you actually shipped.

---

### Q9. What is a foreign key and does it always need an index?

**Answer.** A constraint declaring that a column's values must exist in the parent table's key, with cascade options (RESTRICT/NO ACTION, CASCADE, SET NULL). Most DBs automatically index FK columns (PostgreSQL does; MySQL InnoDB does) because the check needs it — don't assume, check the catalog.

---

### Q10. Explain primary key choices: UUID vs auto-increment vs surrogate?

**Answer.** Auto-increment (BIGINT): tiny, fast, cluster-friendly on InnoDB, but predictable (scrapers) and hard to merge shards. UUIDv4: random, no central authority, but 16 bytes scatter B-tree pages (write amplification) — UUIDv7 (time-ordered) fixes locality. Surrogate keys decouple business identity from storage identity.

---

### Q11. What is transactional outbox and why use it?

**Answer.** To keep 'update DB + publish event' atomic: write the event into an outbox table in the same local transaction as the data change, then a relay (polling or CDC like Debezium) publishes it to the broker. Consumers deduplicate (at-least-once delivery) — this is the standard way to avoid 2PC across services.

---

### Q12. What is the STAR method and why do interviewers prefer it?

**Answer.** Situation, Task, Action, Result — a structured story where the interviewer can see context, your specific contribution (Action is where 'I', not 'we', belongs), and a measurable outcome. It forces concrete evidence over generic claims, which is what behavioral screens actually score.
