# Daily Interview Prep — February 13, 2026

Five questions worked through this session.

---

### Q1. Horizontal vs vertical scaling?

**Answer.** Vertical: bigger machine — simple but capped by hardware and a single point of failure. Horizontal: more machines — requires statelessness or sharded/replicated state, load balancing, and network-aware code, but scales past any single box and allows rolling deploys.

---

### Q2. What is sharding and how do you choose a shard key?

**Answer.** Partition data across databases by a key: hash sharding spreads evenly (but range queries hit all shards), range sharding keeps locality (but risks hot ranges). Choose the key from your query patterns — a hot key (e.g. one user's 1B feed) skews load, so you may double-key (user_id, post_id).

---

### Q3. Explain database replication and the consistency tradeoff.

**Answer.** A primary writes, followers apply via the write-ahead log (async: fast, can lose commits on failover; semi-sync: at least one follower acks; sync: safest, slowest). Reads can go to followers for scale but may return stale data — mitigate with read-your-writes, session tokens, or fencing.

---

### Q4. What is consistent hashing and why do databases/CDNs use it?

**Answer.** Place nodes and keys on a ring (hash space); a key maps to the next node clockwise. Adding/removing a node moves only ~1/n of keys instead of reshuffling everything. Virtual nodes (replicas of a physical node on the ring) even out load and latency.

---

### Q5. How does a CDN work?

**Answer.** An edge network of caches geographically near users, addressed via DNS (CNAME to the CDN, then anycast/nearest-edge selection). Cacheable assets (HTML, JS, media) are served from the edge with cache-control keys; the origin only sees cache misses, cuts latency, and absorbs traffic spikes.

---

### Q6. What is a trie and when would you use one?

**Answer.** A prefix tree where the path from root spells the key. Lookup/cost is O(key length), independent of dataset size. Used for autocomplete, spell-check, IP routing, and deduplicating prefix collisions in hash tables.

---

### Q7. What does union-find (disjoint set) do?

**Answer.** It maintains groups of elements with union() and find(). Path compression + union by rank make each operation ~O(alpha(n)), effectively constant. Classic use: detecting connected components and cycles in undirected graphs.

---

### Q8. BFS vs DFS — when do you pick each?

**Answer.** BFS (queue) finds shortest unweighted paths and is level-order; DFS (stack/recursion) explores deep paths, suits topological sort, cycle detection in directed graphs, and tree traversal. DFS can also blow the stack on deep graphs — use an explicit stack if depth is unbounded.

---

### Q9. What is a skip list and why do databases use it?

**Answer.** A sorted linked list with extra 'express lanes' at higher levels, giving O(log n) expected search with much simpler, lock-friendly code than a balanced tree. LevelDB/RocksDB use it for their memtable because range scans are easy and concurrent insertion is cheap.

---

### Q10. What is a doubly linked list and what is its tradeoff?

**Answer.** Each node holds next and prev pointers, enabling O(1) removal if you have the node, and forward/backward iteration. Cost: 16 extra bytes per node and more pointer writes on mutation.

---

### Q11. How do balanced BSTs (AVL / red-black) stay balanced?

**Answer.** AVL enforces height difference <= 1 via rotations after inserts/deletes — tighter, better for search. Red-black allows larger imbalance but uses at most 2 rotations per insert, so it's favored when insert/delete dominate (e.g., Java TreeMap, Linux CFS).

---

### Q12. What is a sliding window and what does it solve?

**Answer.** Maintain [left, right) over an array with O(1) amortized adds/removes from the ends. Solves fixed-size window max/sum, and variable-size problems like 'longest substring without repeating chars' by shrinking when the constraint breaks.
