# Daily Interview Prep — March 01, 2026

Five questions worked through this session.

---

### Q1. Explain how DNS works in a few sentences.

**Answer.** The resolver queries a recursive resolver, which walks the hierarchy: root servers point to the TLD (.com) servers, which point to the authoritative nameserver for the domain, which answers the A/AAAA/CNAME record. Results are cached at every level per TTL.

---

### Q2. What is the difference between a signal and an exception?

**Answer.** A signal is an asynchronous OS-level interrupt delivered to a process/thread (SIGTERM, SIGKILL, SIGSEGV); a process can install handlers or ignore it, but SIGKILL/SIGSTOP cannot be caught. An exception is a synchronous, in-language control flow mechanism for errors at a known instruction.

---

### Q3. What is the CAP theorem and what do real systems choose?

**Answer.** A distributed system cannot simultaneously guarantee Consistency, Availability, and Partition tolerance — and partitions happen, so the real choice is CP (refuse requests during a partition, e.g. ZooKeeper) or AP (serve stale data, e.g. DynamoDB).

---

### Q4. How does a load balancer work and what are the common algorithms?

**Answer.** It front-ends a pool of servers and routes each connection using round-robin, least-connections, or consistent hashing (minimizes cache invalidation when nodes change). L4 operates on IP/TCP; L7 inspects HTTP (path, headers) and can add TLS termination, retries, and rate limiting.

---

### Q5. Horizontal vs vertical scaling?

**Answer.** Vertical: bigger machine — simple but capped by hardware and a single point of failure. Horizontal: more machines — requires statelessness or sharded/replicated state, load balancing, and network-aware code, but scales past any single box and allows rolling deploys.

---

### Q6. What is a deadlock in a database and how do DBs handle it?

**Answer.** Two transactions each lock rows the other needs (T1 locks A waits for B; T2 locks B waits for A). MySQL InnoDB detects via a wait-for graph and kills the victim (ER_LOCK_DEADLOCK); PostgreSQL waits up to deadlock_timeout then detects and aborts one transaction. App fix: consistent lock ordering, short transactions, retry with backoff.

---

### Q7. What are dirty, non-repeatable and phantom reads?

**Answer.** Dirty read: reading another transaction's uncommitted data (lost if it rolls back). Non-repeatable read: re-reading a committed row that another committed transaction changed. Phantom read: a re-run of a range query returns new rows inserted by another committed transaction. Each maps to the isolation levels above.

---

### Q8. How does a JOIN actually execute?

**Answer.** The planner picks a strategy: nested loop (probe inner per outer row — good with cheap indexes or tiny outer), hash join (build a hash of the smaller side, probe with the larger — the default for large unindexed joins), or merge join (both sides sorted on the key — good for ranges). EXPLAIN shows which one and its estimated cost.
