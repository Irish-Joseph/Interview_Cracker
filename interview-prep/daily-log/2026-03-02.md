# Daily Interview Prep — March 02, 2026

Five questions worked through this session.

---

### Q1. What is sharding and how do you choose a shard key?

**Answer.** Partition data across databases by a key: hash sharding spreads evenly (but range queries hit all shards), range sharding keeps locality (but risks hot ranges). Choose the key from your query patterns — a hot key (e.g. one user's 1B feed) skews load, so you may double-key (user_id, post_id).

---

### Q2. Explain database replication and the consistency tradeoff.

**Answer.** A primary writes, followers apply via the write-ahead log (async: fast, can lose commits on failover; semi-sync: at least one follower acks; sync: safest, slowest). Reads can go to followers for scale but may return stale data — mitigate with read-your-writes, session tokens, or fencing.

---

### Q3. What is consistent hashing and why do databases/CDNs use it?

**Answer.** Place nodes and keys on a ring (hash space); a key maps to the next node clockwise. Adding/removing a node moves only ~1/n of keys instead of reshuffling everything. Virtual nodes (replicas of a physical node on the ring) even out load and latency.

---

### Q4. How does a CDN work?

**Answer.** An edge network of caches geographically near users, addressed via DNS (CNAME to the CDN, then anycast/nearest-edge selection). Cacheable assets (HTML, JS, media) are served from the edge with cache-control keys; the origin only sees cache misses, cuts latency, and absorbs traffic spikes.

---

### Q5. What is rate limiting and name three strategies?

**Answer.** Bounded request acceptance per client/window. Token bucket (smooth bursts up to the bucket size), leaky bucket (constant outflow, smooths bursts), fixed/sliding window counters (simple, counter at window boundaries). Distributed deployments put the counters in Redis with atomic scripts or use an API gateway.

---

### Q6. Why do you want to work here / on this team?

**Answer.** Reference something specific you researched: their architecture posts, an open-source project, a product decision you respect, or a stated engineering value. Generic answers ('great company, good culture') signal you sent 50 applications. Match your stated goals to what the team actually needs.

---

### Q7. How do you handle being stuck on a coding problem for 30 minutes?

**Answer.** Say what you've tried and what specifically is blocking, then ask for a nudge (interviewers expect this — silent spinning loses the round). If unsupervised: re-derive from a smaller case, brute-force first then optimize, and always communicate the partial solution and its complexity.

---

### Q8. What does code review actually check for, from a reviewer's view?

**Answer.** Correctness (does it do the spec?), clarity (naming, structure, dead code), tests (are the important paths covered?), and risk (failure modes, rollback, migration safety). As a reviewer, you're also judging the diff's size — a 3000-line PR is itself a process smell worth flagging.

---

### Q9. Tell me about a time you improved a slow system.

**Answer.** Lead with measurement: what the metric was (p99 latency, throughput), how you found the bottleneck (profiling, slow-query log, flamegraph), the fix, and the before/after numbers. 'I added a cache' without the diagnosis story is the answer that loses senior rounds.

---

### Q10. How do you prioritize when everything is urgent?

**Answer.** Impact x urgency vs effort, but first verify the urgency is real (a 'production is down' that's actually a 2% error rate is different). Make the tradeoff explicit to stakeholders rather than silently absorbing it, and leave room for the actual fire when it lands. Then describe how you communicate the deferral.

---

### Q11. What is the difference between a stack and a queue?

**Answer.** A stack is LIFO — push/pop both happen at the same end; a queue is FIFO — enqueue at the back, dequeue from the front. Stacks model undo, call frames, backtracking; queues model task scheduling, BFS, rate limiting.

---

### Q12. Why does a hash table give O(1) average lookup?

**Answer.** The key is passed through a hash function to index the bucket directly, skipping the scan. It degrades to O(n) when collisions cluster (poor hash or load factor too high), so implementations resize at ~0.7 load and use chaining or open addressing.

---

### Q13. What is a binary search tree and when does it degrade?

**Answer.** A BST keeps left < node < right, giving O(log n) search/insert on average. It degrades to O(n) when the tree becomes a chain (sorted insertions), which is why balanced variants (AVL, red-black) exist.

---

### Q14. Explain a min-heap and its typical use.

**Answer.** A complete binary tree stored in an array where each parent <= its children, so the root is always the minimum. Insert/sift is O(log n); it powers priority queues, top-k problems, Dijkstra, and merge-k-sorted-lists.

---

### Q15. How does an LRU cache work?

**Answer.** A hash map from key to node plus a doubly linked list for recency. On hit, move the node to the front; on insert, evict the back. Both operations are O(1).

---

### Q16. What is a trie and when would you use one?

**Answer.** A prefix tree where the path from root spells the key. Lookup/cost is O(key length), independent of dataset size. Used for autocomplete, spell-check, IP routing, and deduplicating prefix collisions in hash tables.

---

### Q17. What does union-find (disjoint set) do?

**Answer.** It maintains groups of elements with union() and find(). Path compression + union by rank make each operation ~O(alpha(n)), effectively constant. Classic use: detecting connected components and cycles in undirected graphs.
