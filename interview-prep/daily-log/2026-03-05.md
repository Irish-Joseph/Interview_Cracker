# Daily Interview Prep — March 05, 2026

Five questions worked through this session.

---

### Q1. What's the difference between INNER, LEFT, RIGHT and FULL JOIN?

**Answer.** INNER: rows matching in both tables. LEFT: all left rows, NULLs where no match. RIGHT: mirror of LEFT. FULL: all rows from both, NULLs on either side for non-matches. LEFT JOIN with a WHERE on the right table's non-null column silently becomes an INNER JOIN — a classic bug.

---

### Q2. What is normalization and when would you denormalize?

**Answer.** Normalization (1NF..3NF, BCNF) removes redundancy and update anomalies by decomposing relations and keying facts. Denormalize when read latency matters more than write consistency — e.g. embedding an author's name in a posts table or a materialized aggregation — accepting that some write path must keep them in sync.

---

### Q3. What is an index, and why aren't more indexes always better?

**Answer.** A B+tree (typically) mapping key columns to row pointers, turning O(n) scans into O(log n) lookups. Composite indexes follow the leftmost-prefix rule. Costs: every index is written on INSERT/UPDATE/DELETE (write amplification, extra disk), and the planner can pick a bad index. Index for your actual queries, measured via EXPLAIN.

---

### Q4. What is a covering index?

**Answer.** An index that contains all columns the query needs (e.g. INCLUDE in PostgreSQL, or a composite wide enough), so the query is answered from the index alone — no heap 'bookmark lookups'. Common in OLTP for 'index-only scans' on hot read paths.

---

### Q5. Explain a B+tree index.

**Answer.** All data (or row pointers) lives in the leaf level, leaves are linked for range scans, and interior nodes are pure routing keys. Balanced and shallow (3-4 levels for hundreds of millions of rows). The leaf linked list makes sequential range reads a scan of adjacent pages — great for locality.

---

### Q6. What is backtracking?

**Answer.** Build a solution incrementally, and prune the branch as soon as a constraint is violated. Exploring all valid arrangements (N-queens, Sudoku, permutations, subsets) with pruning. Key: make a choice, recurse, undo the choice.

---

### Q7. Explain Kadane's algorithm.

**Answer.** For maximum subarray sum: track best ending here = max(x, best ending here + x) and the global best. Single pass, O(n), O(1) space. The insight is that a negative prefix can never help a future subarray.

---

### Q8. What is topological sort and where is it used?

**Answer.** Ordering the nodes of a DAG so every edge points forward. Computed via Kahn's algorithm (BFS on in-degrees) or DFS finishing times. If a cycle remains, the sort is impossible — which is itself useful for cycle detection. Used in build systems, task scheduling, course prerequisites.

---

### Q9. Greedy vs DP — how do you decide?

**Answer.** Greedy makes the locally best choice and never revisits it — only valid when the greedy-choice property and optimal substructure both hold (interval scheduling, Huffman coding, coin change with canonical coins). DP is the safe general method when subproblems overlap and local choices matter.

---

### Q10. What is A* search?

**Answer.** Best-first search over a graph with cost = g(n) (cost so far) + h(n) (heuristic estimate to goal). With an admissible (never overestimating) heuristic it finds the optimal path; h = 0 reduces to Dijkstra, h = g reduces to greedy best-first. Used in pathfinding and game AI.

---

### Q11. Explain the divide and conquer pattern.

**Answer.** Split the problem into independent subproblems, solve each recursively, combine the results. The recurrence is T(n) = aT(n/b) + O(n^d); the Master Theorem compares a/b^d to decide the bound. Examples: merge sort, matrix multiplication, closest pair.

---

### Q12. How do you find the kth largest element faster than sorting?

**Answer.** Quickselect: partition like quicksort but recurse only into the side containing the kth element — average O(n), worst O(n^2) (fix with median-of-medians pivot or randomization). Or a size-k min-heap: O(n log k), which wins when k << n.

---

### Q13. What is the difference between BFS and Dijkstra on unweighted graphs?

**Answer.** On unweighted graphs Dijkstra degenerates to BFS — every relaxation has the same unit cost, so the heap never reorders anything. BFS is the simpler, faster choice there; keep Dijkstra for weighted edges.
