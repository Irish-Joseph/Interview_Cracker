# Daily Interview Prep — March 15, 2026

Five questions worked through this session.

---

### Q1. When would you use BFS on an adjacency list vs matrix?

**Answer.** Adjacency list: O(V + E) memory, ideal for sparse graphs (the common case). Matrix: O(V^2) memory but O(1) edge-existence checks and easy to combine with matrix operations — fine for dense graphs or small V with repeated queries.

---

### Q2. Process vs thread?

**Answer.** A process is an isolated execution with its own address space and file handles; a thread is a unit of execution inside a process sharing that address space. Threads are cheap to create and communicate via shared memory (at the cost of synchronization); processes are isolated by default and talk via IPC.

---

### Q3. What is virtual memory?

**Answer.** Each process sees a private address space backed by the MMU, which maps virtual pages to physical frames via page tables. It gives isolation, overcommit (map more than RAM), lazy allocation, and the foundation for demand paging and copy-on-write fork.

---

### Q4. TCP vs UDP?

**Answer.** TCP: connection-oriented, reliable, in-order delivery with retransmission, flow and congestion control — for HTTP, databases. UDP: connectionless, no ordering or retransmit, tiny header — for video, DNS, game state, where a late packet is worse than a lost one. QUIC layers reliable streams over UDP.

---

### Q5. What happens when you type a URL and press enter?

**Answer.** DNS resolution (cache -> resolver -> root/TLD/authoritative servers), TCP handshake with the server, then the TLS handshake (certificate validation, key exchange), then the HTTP request/response. The browser parses HTML, fetches sub-resources, and renders.

---

### Q6. What is a doubly linked list and what is its tradeoff?

**Answer.** Each node holds next and prev pointers, enabling O(1) removal if you have the node, and forward/backward iteration. Cost: 16 extra bytes per node and more pointer writes on mutation.

---

### Q7. How do balanced BSTs (AVL / red-black) stay balanced?

**Answer.** AVL enforces height difference <= 1 via rotations after inserts/deletes — tighter, better for search. Red-black allows larger imbalance but uses at most 2 rotations per insert, so it's favored when insert/delete dominate (e.g., Java TreeMap, Linux CFS).

---

### Q8. What is a sliding window and what does it solve?

**Answer.** Maintain [left, right) over an array with O(1) amortized adds/removes from the ends. Solves fixed-size window max/sum, and variable-size problems like 'longest substring without repeating chars' by shrinking when the constraint breaks.

---

### Q9. Explain quicksort and its worst case.

**Answer.** Pick a pivot, partition around it, recurse. Average O(n log n), in-place, cache-friendly. Worst case O(n^2) on sorted input with naive first/last pivot — fixed by randomized or median-of-three pivot. It's not stable.

---

### Q10. Why is merge sort O(n log n) always, and what does it cost?

**Answer.** It splits in half (log n levels) and each level merges in O(n). Guarantees n log n regardless of input and is stable, but needs O(n) auxiliary space — that's the cost.

---

### Q11. What is a count sort / radix sort and when is it valid?

**Answer.** Counting sort buckets by integer value in O(n + k) — linear when k is bounded, so it beats comparison sort's n log n floor. Radix sort generalizes it digit-by-digit. Only works on bounded integers (or fixed-length keys).
