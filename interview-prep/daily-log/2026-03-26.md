# Daily Interview Prep — March 26, 2026

Five questions worked through this session.

---

### Q1. What is the difference between a stack and a queue?

**Answer.** A stack is LIFO — push/pop both happen at the same end; a queue is FIFO — enqueue at the back, dequeue from the front. Stacks model undo, call frames, backtracking; queues model task scheduling, BFS, rate limiting.

---

### Q2. Why does a hash table give O(1) average lookup?

**Answer.** The key is passed through a hash function to index the bucket directly, skipping the scan. It degrades to O(n) when collisions cluster (poor hash or load factor too high), so implementations resize at ~0.7 load and use chaining or open addressing.

---

### Q3. What is a binary search tree and when does it degrade?

**Answer.** A BST keeps left < node < right, giving O(log n) search/insert on average. It degrades to O(n) when the tree becomes a chain (sorted insertions), which is why balanced variants (AVL, red-black) exist.

---

### Q4. Explain a min-heap and its typical use.

**Answer.** A complete binary tree stored in an array where each parent <= its children, so the root is always the minimum. Insert/sift is O(log n); it powers priority queues, top-k problems, Dijkstra, and merge-k-sorted-lists.

---

### Q5. How does an LRU cache work?

**Answer.** A hash map from key to node plus a doubly linked list for recency. On hit, move the node to the front; on insert, evict the back. Both operations are O(1).

---

### Q6. What is a count sort / radix sort and when is it valid?

**Answer.** Counting sort buckets by integer value in O(n + k) — linear when k is bounded, so it beats comparison sort's n log n floor. Radix sort generalizes it digit-by-digit. Only works on bounded integers (or fixed-length keys).

---

### Q7. What do we mean when we say an algorithm is O(n log n)?

**Answer.** Runtime grows proportionally to n log n: n log n = n x log n, n x log2 n = n x 10. Big-O hides constants and lower-order terms, so 10n log n is also O(n log n). It describes the asymptotic upper bound of the worst-case behavior we analyzed.

---

### Q8. Explain the two-pointer technique.

**Answer.** Keep left and right pointers moving inward (or both moving forward) to exploit monotonic structure — sorted arrays, prefix structure, window validity. Reduces brute-force O(n^2) to O(n) for problems like two-sum on sorted arrays, container-with-most-water, and palindrome checks.

---

### Q9. When is binary search the right tool, and what's the classic bug?

**Answer.** Use it on any monotonic predicate (sorted array, or 'find first true over a boolean space'), giving O(log n). Classic bugs: integer overflow in mid = (lo+hi)/2 (use lo + (hi-lo)/2), off-by-one on update bounds, and wrong loop invariant (use [lo, hi) or consistently <=).
