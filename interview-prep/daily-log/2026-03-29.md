# Daily Interview Prep — March 29, 2026

Five questions worked through this session.

---

### Q1. What do we mean when we say an algorithm is O(n log n)?

**Answer.** Runtime grows proportionally to n log n: n log n = n x log n, n x log2 n = n x 10. Big-O hides constants and lower-order terms, so 10n log n is also O(n log n). It describes the asymptotic upper bound of the worst-case behavior we analyzed.

---

### Q2. Explain the two-pointer technique.

**Answer.** Keep left and right pointers moving inward (or both moving forward) to exploit monotonic structure — sorted arrays, prefix structure, window validity. Reduces brute-force O(n^2) to O(n) for problems like two-sum on sorted arrays, container-with-most-water, and palindrome checks.

---

### Q3. When is binary search the right tool, and what's the classic bug?

**Answer.** Use it on any monotonic predicate (sorted array, or 'find first true over a boolean space'), giving O(log n). Classic bugs: integer overflow in mid = (lo+hi)/2 (use lo + (hi-lo)/2), off-by-one on update bounds, and wrong loop invariant (use [lo, hi) or consistently <=).

---

### Q4. Describe Dijkstra's algorithm and its limitation.

**Answer.** Greedy shortest-path from one source using a min-heap: settle the closest unsettled node, relax edges. O((V+E) log V). Fails with negative edge weights because a settled node's distance can still decrease — use Bellman-Ford there.

---

### Q5. What is dynamic programming, and what makes a problem solvable with it?

**Answer.** Break a problem into overlapping subproblems, solve each once, store the result (memoization/table). Requirements: optimal substructure (optimal solution built from optimal sub-solutions) and overlapping subproblems. Example: Fibonacci, knapsack, longest common subsequence.

---

### Q6. Process vs thread?

**Answer.** A process is an isolated execution with its own address space and file handles; a thread is a unit of execution inside a process sharing that address space. Threads are cheap to create and communicate via shared memory (at the cost of synchronization); processes are isolated by default and talk via IPC.

---

### Q7. What is virtual memory?

**Answer.** Each process sees a private address space backed by the MMU, which maps virtual pages to physical frames via page tables. It gives isolation, overcommit (map more than RAM), lazy allocation, and the foundation for demand paging and copy-on-write fork.

---

### Q8. TCP vs UDP?

**Answer.** TCP: connection-oriented, reliable, in-order delivery with retransmission, flow and congestion control — for HTTP, databases. UDP: connectionless, no ordering or retransmit, tiny header — for video, DNS, game state, where a late packet is worse than a lost one. QUIC layers reliable streams over UDP.

---

### Q9. What happens when you type a URL and press enter?

**Answer.** DNS resolution (cache -> resolver -> root/TLD/authoritative servers), TCP handshake with the server, then the TLS handshake (certificate validation, key exchange), then the HTTP request/response. The browser parses HTML, fetches sub-resources, and renders.

---

### Q10. What is a deadlock and what are its conditions?

**Answer.** Two or more threads each hold a resource the other needs, so none can proceed. Needs four conditions (Coffman): mutual exclusion, hold-and-wait, no preemption, circular wait. Break any one — common practice: impose a global lock ordering to kill circular wait, or use try-lock with timeout/backoff.

---

### Q11. What is a context switch and what does it cost?

**Answer.** The OS saving the current thread's CPU state (registers, PC, stack pointer) to its PCB and restoring another thread's. Costs a few microseconds plus cache/TLB pollution — millions of involuntary switches per second can dominate runtime, which is why thread pools exist.

---

### Q12. Explain TCP three-way handshake and why three packets?

**Answer.** Client SYN(seq=x) -> server SYN-ACK(seq=y, ack=x+1) -> client ACK(ack=y+1). Three packets ensure both sides' send and receive paths work and both initial sequence numbers are exchanged. Two would leave one direction unconfirmed and allows stale duplicated SYNs to open connections.

---

### Q13. What is the GIL in CPython?

**Answer.** A global interpreter lock that lets only one thread execute Python bytecode at a time, protecting refcounts. It serializes CPU-bound Python threads, so you use multiprocessing for CPU work and threads still help for I/O (the lock is released during blocking calls).

---

### Q14. What is a memory leak?

**Answer.** Memory that is no longer reachable through any pointer but was never freed (or is kept alive by an unintended reference). Symptoms: slow RSS growth, eventual OOM. Sources: unremoved listeners/cache entries, reference cycles (in refcounted runtimes without GC), leaked native handles.
