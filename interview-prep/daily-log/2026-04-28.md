# Daily Interview Prep — April 28, 2026

Focus: OS & networking. 2 questions worked through this session.

---

### Q1. How does a CDN work?

**Answer.** An edge network of caches geographically near users, addressed via DNS (CNAME to the CDN, then anycast/nearest-edge selection). Cacheable assets (HTML, JS, media) are served from the edge with cache-control keys; the origin only sees cache misses, cuts latency, and absorbs traffic spikes.

---

### Q2. What is rate limiting and name three strategies?

**Answer.** Bounded request acceptance per client/window. Token bucket (smooth bursts up to the bucket size), leaky bucket (constant outflow, smooths bursts), fixed/sliding window counters (simple, counter at window boundaries). Distributed deployments put the counters in Redis with atomic scripts or use an API gateway.

---

### Q3. TCP vs UDP?

**Answer.** TCP: connection-oriented, reliable, in-order delivery with retransmission, flow and congestion control — for HTTP, databases. UDP: connectionless, no ordering or retransmit, tiny header — for video, DNS, game state, where a late packet is worse than a lost one. QUIC layers reliable streams over UDP.

---

### Q4. What happens when you type a URL and press enter?

**Answer.** DNS resolution (cache -> resolver -> root/TLD/authoritative servers), TCP handshake with the server, then the TLS handshake (certificate validation, key exchange), then the HTTP request/response. The browser parses HTML, fetches sub-resources, and renders.
