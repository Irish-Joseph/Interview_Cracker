# Daily Interview Prep — April 29, 2026

Focus: system design. 2 questions worked through this session.

---

### Q1. What is a message queue and when would you use Kafka vs RabbitMQ?

**Answer.** A broker that decouples producers from consumers via durable, asynchronous messages. Kafka is a replicated, partitioned log — high throughput, replayable, event-sourcing/audit trails. RabbitMQ is a flexible work-queue router — lower latency per message, rich routing, but not a replay log.

---

### Q2. Microservices vs monolith?

**Answer.** Monolith: one deployable, shared database, simple transactions and debugging, coupled releases. Microservices: independent deploy/scale per service, polyglot persistence, isolated failure domains — at the cost of network latency, distributed-transaction complexity (sagas), and operational burden (tracing, versioning contracts).

---

### Q3. What is copy-on-write and where is it used?

**Answer.** Share read-only pages between users; on first write, the kernel allocates a new page and copies, then points the writer at it. Used in fork() (child shares the parent's pages until it writes), in ZFS/Btrfs, and in persistent data structures (Clojure's atoms, Rust's Arc-based immutability patterns).

---

### Q4. What is HTTP/2 and how does it fix head-of-line blocking at one layer but create it at another?

**Answer.** Multiplexes many streams over one TCP connection with binary framing and header compression (HPACK), killing HTTP/1.1's one-request-per-connection stalls. But TCP-level retransmission still blocks all streams — that's why HTTP/3 moved to QUIC/UDP.

---

### Q5. What is a file descriptor and why is it just an integer?

**Answer.** An index into the per-process table of open file handles (socket, pipe, regular file, terminal). Everything is a stream of bytes to the kernel, so dup/pipe/redirect work uniformly — /dev/null, socket 3, and an open file all share the same syscall interface.
