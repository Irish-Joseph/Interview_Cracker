# Daily Interview Prep — May 26, 2026

Focus: design + behavioral. 2 questions worked through this session.

---

### Q1. Explain quicksort and its worst case.

**Answer.** Pick a pivot, partition around it, recurse. Average O(n log n), in-place, cache-friendly. Worst case O(n^2) on sorted input with naive first/last pivot — fixed by randomized or median-of-three pivot. It's not stable.

---

### Q2. Why is merge sort O(n log n) always, and what does it cost?

**Answer.** It splits in half (log n levels) and each level merges in O(n). Guarantees n log n regardless of input and is stable, but needs O(n) auxiliary space — that's the cost.

---

### Q3. What is a doubly linked list and what is its tradeoff?

**Answer.** Each node holds next and prev pointers, enabling O(1) removal if you have the node, and forward/backward iteration. Cost: 16 extra bytes per node and more pointer writes on mutation.

---

### Q4. How do balanced BSTs (AVL / red-black) stay balanced?

**Answer.** AVL enforces height difference <= 1 via rotations after inserts/deletes — tighter, better for search. Red-black allows larger imbalance but uses at most 2 rotations per insert, so it's favored when insert/delete dominate (e.g., Java TreeMap, Linux CFS).

---

### Q5. What is a sliding window and what does it solve?

**Answer.** Maintain [left, right) over an array with O(1) amortized adds/removes from the ends. Solves fixed-size window max/sum, and variable-size problems like 'longest substring without repeating chars' by shrinking when the constraint breaks.

### Q8. What is a count sort / radix sort and when is it valid?

**Answer.** Counting sort buckets by integer value in O(n + k) — linear when k is bounded, so it beats comparison sort's n log n floor. Radix sort generalizes it digit-by-digit. Only works on bounded integers (or fixed-length keys).

---

### Q9. What do we mean when we say an algorithm is O(n log n)?

**Answer.** Runtime grows proportionally to n log n: n log n = n x log n, n x log2 n = n x 10. Big-O hides constants and lower-order terms, so 10n log n is also O(n log n). It describes the asymptotic upper bound of the worst-case behavior we analyzed.

---

### Q10. Explain the two-pointer technique.

**Answer.** Keep left and right pointers moving inward (or both moving forward) to exploit monotonic structure — sorted arrays, prefix structure, window validity. Reduces brute-force O(n^2) to O(n) for problems like two-sum on sorted arrays, container-with-most-water, and palindrome checks.

---

### Q11. When is binary search the right tool, and what's the classic bug?

**Answer.** Use it on any monotonic predicate (sorted array, or 'find first true over a boolean space'), giving O(log n). Classic bugs: integer overflow in mid = (lo+hi)/2 (use lo + (hi-lo)/2), off-by-one on update bounds, and wrong loop invariant (use [lo, hi) or consistently <=).
