# Daily Interview Prep — June 03, 2026

Focus: OS & networking. 3 questions worked through this session.

### Q1. What is dynamic programming, and what makes a problem solvable with it?

**Answer.** Break a problem into overlapping subproblems, solve each once, store the result (memoization/table). Requirements: optimal substructure (optimal solution built from optimal sub-solutions) and overlapping subproblems. Example: Fibonacci, knapsack, longest common subsequence.

---

### Q2. Memoization vs tabulation?

**Answer.** Memoization is top-down recursion with a cache; tabulation is bottom-up iteration filling a table. Same complexity; tabulation removes recursion overhead and can enable space reduction (keep only the last 2 rows), while memoization is often easier to derive from the recurrence.

---

### Q3. What is backtracking?

**Answer.** Build a solution incrementally, and prune the branch as soon as a constraint is violated. Exploring all valid arrangements (N-queens, Sudoku, permutations, subsets) with pruning. Key: make a choice, recurse, undo the choice.

---

### Q4. What is a foreign key and does it always need an index?

**Answer.** A constraint declaring that a column's values must exist in the parent table's key, with cascade options (RESTRICT/NO ACTION, CASCADE, SET NULL). Most DBs automatically index FK columns (PostgreSQL does; MySQL InnoDB does) because the check needs it — don't assume, check the catalog.

---

### Q5. Explain primary key choices: UUID vs auto-increment vs surrogate?

**Answer.** Auto-increment (BIGINT): tiny, fast, cluster-friendly on InnoDB, but predictable (scrapers) and hard to merge shards. UUIDv4: random, no central authority, but 16 bytes scatter B-tree pages (write amplification) — UUIDv7 (time-ordered) fixes locality. Surrogate keys decouple business identity from storage identity.
