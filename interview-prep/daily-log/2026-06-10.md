### Q1. What happens when you type a URL and press enter?

**Answer.** DNS resolution (cache -> resolver -> root/TLD/authoritative servers), TCP handshake with the server, then the TLS handshake (certificate validation, key exchange), then the HTTP request/response. The browser parses HTML, fetches sub-resources, and renders.

---

### Q2. What is a deadlock and what are its conditions?

**Answer.** Two or more threads each hold a resource the other needs, so none can proceed. Needs four conditions (Coffman): mutual exclusion, hold-and-wait, no preemption, circular wait. Break any one — common practice: impose a global lock ordering to kill circular wait, or use try-lock with timeout/backoff.

---

### Q3. Explain how DNS works in a few sentences.

**Answer.** The resolver queries a recursive resolver, which walks the hierarchy: root servers point to the TLD (.com) servers, which point to the authoritative nameserver for the domain, which answers the A/AAAA/CNAME record. Results are cached at every level per TTL.

---

### Q4. What is the difference between a signal and an exception?

**Answer.** A signal is an asynchronous OS-level interrupt delivered to a process/thread (SIGTERM, SIGKILL, SIGSEGV); a process can install handlers or ignore it, but SIGKILL/SIGSTOP cannot be caught. An exception is a synchronous, in-language control flow mechanism for errors at a known instruction.
