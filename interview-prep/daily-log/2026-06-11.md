# Daily Interview Prep — June 11, 2026

Focus: core CS. 5 questions worked through this session.

---

### Q1. What is a context switch and what does it cost?

**Answer.** The OS saving the current thread's CPU state (registers, PC, stack pointer) to its PCB and restoring another thread's. Costs a few microseconds plus cache/TLB pollution — millions of involuntary switches per second can dominate runtime, which is why thread pools exist.

---

### Q2. Explain TCP three-way handshake and why three packets?

**Answer.** Client SYN(seq=x) -> server SYN-ACK(seq=y, ack=x+1) -> client ACK(ack=y+1). Three packets ensure both sides' send and receive paths work and both initial sequence numbers are exchanged. Two would leave one direction unconfirmed and allows stale duplicated SYNs to open connections.

---

### Q3. What is the GIL in CPython?

**Answer.** A global interpreter lock that lets only one thread execute Python bytecode at a time, protecting refcounts. It serializes CPU-bound Python threads, so you use multiprocessing for CPU work and threads still help for I/O (the lock is released during blocking calls).

---

### Q4. What is a memory leak?

**Answer.** Memory that is no longer reachable through any pointer but was never freed (or is kept alive by an unintended reference). Symptoms: slow RSS growth, eventual OOM. Sources: unremoved listeners/cache entries, reference cycles (in refcounted runtimes without GC), leaked native handles.

---

### Q5. Explain reference counting vs tracing garbage collection.

**Answer.** Refcounting frees an object the moment its count hits zero — simple and immediate, but cannot collect cycles and the per-pointer overhead is real. Tracing GC (mark-and-sweep, generational, e.g. G1/ZGC) scans from roots, handles cycles, but introduces pauses or pauses-hiding (ZGC uses colored pointers for concurrent collection).

---

### Q6. What is a message queue and when would you use Kafka vs RabbitMQ?

**Answer.** A broker that decouples producers from consumers via durable, asynchronous messages. Kafka is a replicated, partitioned log — high throughput, replayable, event-sourcing/audit trails. RabbitMQ is a flexible work-queue router — lower latency per message, rich routing, but not a replay log.

---

### Q7. Microservices vs monolith?

**Answer.** Monolith: one deployable, shared database, simple transactions and debugging, coupled releases. Microservices: independent deploy/scale per service, polyglot persistence, isolated failure domains — at the cost of network latency, distributed-transaction complexity (sagas), and operational burden (tracing, versioning contracts).

---

### Q8. What is a B-tree and why do databases use it for indexes?

**Answer.** A multi-way balanced tree where each node holds many keys and child pointers, tuned so one node = one disk page. Height ~3-4 holds hundreds of millions of keys, so a point lookup is 3-4 page reads. Range scans are sequential page walks — better locality than a B+tree's leaf linked list... (B+trees are the usual choice; B-trees store data in all nodes).

---

### Q9. What is a database connection pool and why is it needed?

**Answer.** Connections are expensive to create (TCP + auth + TLS, tens of ms); a pool keeps N warm connections for the app to borrow/return. Pool size must respect the DB's max_connections — a common outage: 200 app nodes x pool of 20 = 4000 connections vs DB limit 1000. PgBouncer proxies to share physical connections.

---

### Q10. What does idempotency mean and how do you make writes idempotent?

**Answer.** Repeating the operation has no additional effect. Techniques: client-generated idempotency keys deduplicated server-side, PUT (replace, not append) semantics, and unique constraints (re-insert hits the constraint instead of duplicating). Needed for retries over networks where 'did it land?' is unknowable.

---

### Q11. How would you design a short URL service (bit.ly)?

**Answer.** Hash the long URL (or use a monotonic counter / base62 of an auto-increment id) to a 7-char code — counter avoids hash collisions and is cache-friendly. Store code->URL in a KV store or sharded DB, 301 redirect (caches the mapping in browsers) or 302 if you need click analytics. Handle load with a CDN + hot-key replication.

---

### Q12. What is a write-ahead log (WAL) and why is it important?

**Answer.** Every change is appended to a durable log before being applied to the data structures; crash recovery replays the log (redo) and rolls back uncommitted work (undo). It's what makes a database durable after a power loss, and the same log powers replication, point-in-time recovery, and compaction in LSM stores.
