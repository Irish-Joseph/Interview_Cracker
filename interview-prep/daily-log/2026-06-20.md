# Daily Interview Prep — June 20, 2026

Focus: algorithms. Questions worked through this session.

---

### Q1. How does a load balancer work and what are the common algorithms?

**Answer.** It front-ends a pool of servers and routes each connection using round-robin, least-connections, or consistent hashing (minimizes cache invalidation when nodes change). L4 operates on IP/TCP; L7 inspects HTTP (path, headers) and can add TLS termination, retries, and rate limiting.

---

### Q2. Horizontal vs vertical scaling?

**Answer.** Vertical: bigger machine — simple but capped by hardware and a single point of failure. Horizontal: more machines — requires statelessness or sharded/replicated state, load balancing, and network-aware code, but scales past any single box and allows rolling deploys.

---

### Q3. What is sharding and how do you choose a shard key?

**Answer.** Partition data across databases by a key: hash sharding spreads evenly (but range queries hit all shards), range sharding keeps locality (but risks hot ranges). Choose the key from your query patterns — a hot key (e.g. one user's 1B feed) skews load, so you may double-key (user_id, post_id).

---

### Q4. Explain database replication and the consistency tradeoff.

**Answer.** A primary writes, followers apply via the write-ahead log (async: fast, can lose commits on failover; semi-sync: at least one follower acks; sync: safest, slowest). Reads can go to followers for scale but may return stale data — mitigate with read-your-writes, session tokens, or fencing.

---

### Q5. What is consistent hashing and why do databases/CDNs use it?

**Answer.** Place nodes and keys on a ring (hash space); a key maps to the next node clockwise. Adding/removing a node moves only ~1/n of keys instead of reshuffling everything. Virtual nodes (replicas of a physical node on the ring) even out load and latency.

---

### Q6. How does a CDN work?

**Answer.** An edge network of caches geographically near users, addressed via DNS (CNAME to the CDN, then anycast/nearest-edge selection). Cacheable assets (HTML, JS, media) are served from the edge with cache-control keys; the origin only sees cache misses, cuts latency, and absorbs traffic spikes.

---

### Q7. What is rate limiting and name three strategies?

**Answer.** Bounded request acceptance per client/window. Token bucket (smooth bursts up to the bucket size), leaky bucket (constant outflow, smooths bursts), fixed/sliding window counters (simple, counter at window boundaries). Distributed deployments put the counters in Redis with atomic scripts or use an API gateway.

---

### Q8. What is a message queue and when would you use Kafka vs RabbitMQ?

**Answer.** A broker that decouples producers from consumers via durable, asynchronous messages. Kafka is a replicated, partitioned log — high throughput, replayable, event-sourcing/audit trails. RabbitMQ is a flexible work-queue router — lower latency per message, rich routing, but not a replay log.

---

### Q9. Microservices vs monolith?

**Answer.** Monolith: one deployable, shared database, simple transactions and debugging, coupled releases. Microservices: independent deploy/scale per service, polyglot persistence, isolated failure domains — at the cost of network latency, distributed-transaction complexity (sagas), and operational burden (tracing, versioning contracts).

---

### Q10. What is a B-tree and why do databases use it for indexes?

**Answer.** A multi-way balanced tree where each node holds many keys and child pointers, tuned so one node = one disk page. Height ~3-4 holds hundreds of millions of keys, so a point lookup is 3-4 page reads. Range scans are sequential page walks — better locality than a B+tree's leaf linked list... (B+trees are the usual choice; B-trees store data in all nodes).
