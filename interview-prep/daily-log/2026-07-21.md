# Daily Interview Prep — July 21, 2026

Focus: core CS. 2 questions worked through this session.

---

### Q1. BFS vs DFS — when do you pick each?

**Answer.** BFS (queue) finds shortest unweighted paths and is level-order; DFS (stack/recursion) explores deep paths, suits topological sort, cycle detection in directed graphs, and tree traversal. DFS can also blow the stack on deep graphs — use an explicit stack if depth is unbounded.

---

### Q2. What is a skip list and why do databases use it?

**Answer.** A sorted linked list with extra 'express lanes' at higher levels, giving O(log n) expected search with much simpler, lock-friendly code than a balanced tree. LevelDB/RocksDB use it for their memtable because range scans are easy and concurrent insertion is cheap.

---

### Q3. What is the difference between BFS and Dijkstra on unweighted graphs?

**Answer.** On unweighted graphs Dijkstra degenerates to BFS — every relaxation has the same unit cost, so the heap never reorders anything. BFS is the simpler, faster choice there; keep Dijkstra for weighted edges.

---

### Q4. When would you use BFS on an adjacency list vs matrix?

**Answer.** Adjacency list: O(V + E) memory, ideal for sparse graphs (the common case). Matrix: O(V^2) memory but O(1) edge-existence checks and easy to combine with matrix operations — fine for dense graphs or small V with repeated queries.

---

### Q5. Process vs thread?

**Answer.** A process is an isolated execution with its own address space and file handles; a thread is a unit of execution inside a process sharing that address space. Threads are cheap to create and communicate via shared memory (at the cost of synchronization); processes are isolated by default and talk via IPC.

---

### Q6. What is virtual memory?

**Answer.** Each process sees a private address space backed by the MMU, which maps virtual pages to physical frames via page tables. It gives isolation, overcommit (map more than RAM), lazy allocation, and the foundation for demand paging and copy-on-write fork.

---

### Q7. TCP vs UDP?

**Answer.** TCP: connection-oriented, reliable, in-order delivery with retransmission, flow and congestion control — for HTTP, databases. UDP: connectionless, no ordering or retransmit, tiny header — for video, DNS, game state, where a late packet is worse than a lost one. QUIC layers reliable streams over UDP.

---

### Q8. What happens when you type a URL and press enter?

**Answer.** DNS resolution (cache -> resolver -> root/TLD/authoritative servers), TCP handshake with the server, then the TLS handshake (certificate validation, key exchange), then the HTTP request/response. The browser parses HTML, fetches sub-resources, and renders.

---

### Q9. What is a deadlock and what are its conditions?

**Answer.** Two or more threads each hold a resource the other needs, so none can proceed. Needs four conditions (Coffman): mutual exclusion, hold-and-wait, no preemption, circular wait. Break any one — common practice: impose a global lock ordering to kill circular wait, or use try-lock with timeout/backoff.
