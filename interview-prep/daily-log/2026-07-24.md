# Daily Interview Prep — July 24, 2026

Focus: SQL & transactions. 4 questions worked through this session.

---

### Q1. What is dynamic programming, and what makes a problem solvable with it?

**Answer.** Break a problem into overlapping subproblems, solve each once, store the result (memoization/table). Requirements: optimal substructure (optimal solution built from optimal sub-solutions) and overlapping subproblems. Example: Fibonacci, knapsack, longest common subsequence.

---

### Q2. Memoization vs tabulation?

**Answer.** Memoization is top-down recursion with a cache; tabulation is bottom-up iteration filling a table. Same complexity; tabulation removes recursion overhead and can enable space reduction (keep only the last 2 rows), while memoization is often easier to derive from the recurrence.

---

### Q3. What is backtracking?

**Answer.** Build a solution incrementally, and prune the branch as soon as a constraint is violated. Exploring all valid arrangements (N-queens, Sudoku, permutations, subsets) with pruning. Key: make a choice, recurse, undo the choice.

---

### Q4. Explain Kadane's algorithm.

**Answer.** For maximum subarray sum: track best ending here = max(x, best ending here + x) and the global best. Single pass, O(n), O(1) space. The insight is that a negative prefix can never help a future subarray.

---

### Q5. Explain reference counting vs tracing garbage collection.

**Answer.** Refcounting frees an object the moment its count hits zero — simple and immediate, but cannot collect cycles and the per-pointer overhead is real. Tracing GC (mark-and-sweep, generational, e.g. G1/ZGC) scans from roots, handles cycles, but introduces pauses or pauses-hiding (ZGC uses colored pointers for concurrent collection).

---

### Q6. What is copy-on-write and where is it used?

**Answer.** Share read-only pages between users; on first write, the kernel allocates a new page and copies, then points the writer at it. Used in fork() (child shares the parent's pages until it writes), in ZFS/Btrfs, and in persistent data structures (Clojure's atoms, Rust's Arc-based immutability patterns).

---

### Q7. What is HTTP/2 and how does it fix head-of-line blocking at one layer but create it at another?

**Answer.** Multiplexes many streams over one TCP connection with binary framing and header compression (HPACK), killing HTTP/1.1's one-request-per-connection stalls. But TCP-level retransmission still blocks all streams — that's why HTTP/3 moved to QUIC/UDP.

---

### Q8. What is a file descriptor and why is it just an integer?

**Answer.** An index into the per-process table of open file handles (socket, pipe, regular file, terminal). Everything is a stream of bytes to the kernel, so dup/pipe/redirect work uniformly — /dev/null, socket 3, and an open file all share the same syscall interface.

---

### Q9. Explain how DNS works in a few sentences.

**Answer.** The resolver queries a recursive resolver, which walks the hierarchy: root servers point to the TLD (.com) servers, which point to the authoritative nameserver for the domain, which answers the A/AAAA/CNAME record. Results are cached at every level per TTL.

---

### Q10. What is the difference between a signal and an exception?

**Answer.** A signal is an asynchronous OS-level interrupt delivered to a process/thread (SIGTERM, SIGKILL, SIGSEGV); a process can install handlers or ignore it, but SIGKILL/SIGSTOP cannot be caught. An exception is a synchronous, in-language control flow mechanism for errors at a known instruction.

---

### Q11. What is the CAP theorem and what do real systems choose?

**Answer.** A distributed system cannot simultaneously guarantee Consistency, Availability, and Partition tolerance — and partitions happen, so the real choice is CP (refuse requests during a partition, e.g. ZooKeeper) or AP (serve stale data, e.g. DynamoDB).

---

### Q12. How does a load balancer work and what are the common algorithms?

**Answer.** It front-ends a pool of servers and routes each connection using round-robin, least-connections, or consistent hashing (minimizes cache invalidation when nodes change). L4 operates on IP/TCP; L7 inspects HTTP (path, headers) and can add TLS termination, retries, and rate limiting.
