# Daily Interview Prep — July 25, 2026

Focus: core CS. 3 questions worked through this session.

---

### Q1. What is topological sort and where is it used?

**Answer.** Ordering the nodes of a DAG so every edge points forward. Computed via Kahn's algorithm (BFS on in-degrees) or DFS finishing times. If a cycle remains, the sort is impossible — which is itself useful for cycle detection. Used in build systems, task scheduling, course prerequisites.

---

### Q2. Greedy vs DP — how do you decide?

**Answer.** Greedy makes the locally best choice and never revisits it — only valid when the greedy-choice property and optimal substructure both hold (interval scheduling, Huffman coding, coin change with canonical coins). DP is the safe general method when subproblems overlap and local choices matter.

---

### Q3. What is A* search?

**Answer.** Best-first search over a graph with cost = g(n) (cost so far) + h(n) (heuristic estimate to goal). With an admissible (never overestimating) heuristic it finds the optimal path; h = 0 reduces to Dijkstra, h = g reduces to greedy best-first. Used in pathfinding and game AI.

---

### Q4. Horizontal vs vertical scaling?

**Answer.** Vertical: bigger machine — simple but capped by hardware and a single point of failure. Horizontal: more machines — requires statelessness or sharded/replicated state, load balancing, and network-aware code, but scales past any single box and allows rolling deploys.

---

### Q5. What is sharding and how do you choose a shard key?

**Answer.** Partition data across databases by a key: hash sharding spreads evenly (but range queries hit all shards), range sharding keeps locality (but risks hot ranges). Choose the key from your query patterns — a hot key (e.g. one user's 1B feed) skews load, so you may double-key (user_id, post_id).

---

### Q6. Explain database replication and the consistency tradeoff.

**Answer.** A primary writes, followers apply via the write-ahead log (async: fast, can lose commits on failover; semi-sync: at least one follower acks; sync: safest, slowest). Reads can go to followers for scale but may return stale data — mitigate with read-your-writes, session tokens, or fencing.
