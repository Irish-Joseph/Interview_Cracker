# Daily Interview Prep — August 22, 2026

Focus: OS & networking. 1 question worked through this session.

---

### Q1. What is normalization and when would you denormalize?

**Answer.** Normalization (1NF..3NF, BCNF) removes redundancy and update anomalies by decomposing relations and keying facts. Denormalize when read latency matters more than write consistency — e.g. embedding an author's name in a posts table or a materialized aggregation — accepting that some write path must keep them in sync.

---

### Q2. TCP vs UDP?

**Answer.** TCP: connection-oriented, reliable, in-order delivery with retransmission, flow and congestion control — for HTTP, databases. UDP: connectionless, no ordering or retransmit, tiny header — for video, DNS, game state, where a late packet is worse than a lost one. QUIC layers reliable streams over UDP.

---

### Q3. What happens when you type a URL and press enter?

**Answer.** DNS resolution (cache -> resolver -> root/TLD/authoritative servers), TCP handshake with the server, then the TLS handshake (certificate validation, key exchange), then the HTTP request/response. The browser parses HTML, fetches sub-resources, and renders.

---

### Q4. What is a deadlock and what are its conditions?

**Answer.** Two or more threads each hold a resource the other needs, so none can proceed. Needs four conditions (Coffman): mutual exclusion, hold-and-wait, no preemption, circular wait. Break any one — common practice: impose a global lock ordering to kill circular wait, or use try-lock with timeout/backoff.

---

### Q5. What is a context switch and what does it cost?

**Answer.** The OS saving the current thread's CPU state (registers, PC, stack pointer) to its PCB and restoring another thread's. Costs a few microseconds plus cache/TLB pollution — millions of involuntary switches per second can dominate runtime, which is why thread pools exist.

---

### Q6. Explain TCP three-way handshake and why three packets?

**Answer.** Client SYN(seq=x) -> server SYN-ACK(seq=y, ack=x+1) -> client ACK(ack=y+1). Three packets ensure both sides' send and receive paths work and both initial sequence numbers are exchanged. Two would leave one direction unconfirmed and allows stale duplicated SYNs to open connections.

---

### Q7. What is the GIL in CPython?

**Answer.** A global interpreter lock that lets only one thread execute Python bytecode at a time, protecting refcounts. It serializes CPU-bound Python threads, so you use multiprocessing for CPU work and threads still help for I/O (the lock is released during blocking calls).

---

### Q8. What is a memory leak?

**Answer.** Memory that is no longer reachable through any pointer but was never freed (or is kept alive by an unintended reference). Symptoms: slow RSS growth, eventual OOM. Sources: unremoved listeners/cache entries, reference cycles (in refcounted runtimes without GC), leaked native handles.

---

### Q9. Explain reference counting vs tracing garbage collection.

**Answer.** Refcounting frees an object the moment its count hits zero — simple and immediate, but cannot collect cycles and the per-pointer overhead is real. Tracing GC (mark-and-sweep, generational, e.g. G1/ZGC) scans from roots, handles cycles, but introduces pauses or pauses-hiding (ZGC uses colored pointers for concurrent collection).

---

### Q10. What is copy-on-write and where is it used?

**Answer.** Share read-only pages between users; on first write, the kernel allocates a new page and copies, then points the writer at it. Used in fork() (child shares the parent's pages until it writes), in ZFS/Btrfs, and in persistent data structures (Clojure's atoms, Rust's Arc-based immutability patterns).

---

### Q11. What is HTTP/2 and how does it fix head-of-line blocking at one layer but create it at another?

**Answer.** Multiplexes many streams over one TCP connection with binary framing and header compression (HPACK), killing HTTP/1.1's one-request-per-connection stalls. But TCP-level retransmission still blocks all streams — that's why HTTP/3 moved to QUIC/UDP.
